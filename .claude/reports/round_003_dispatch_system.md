# Round 003 — 任务调度中心搭建

**日期**: 2026-05-27
**背景**: 上级要求建立自我迭代的调度系统，让多个 Claude Code 工人自动协作，不需要手动下指令。

---

## 做了什么

### 1. 调度主板 (`.claude/dispatch/BOARD.md`)

- 7 个任务入队，分 P0/P1/P2 三级优先级
- 4 个工人 slot（alpha/beta/gamma/delta），按能力匹配
- 关键路径：T-001 → T-005 → T-006 → T-007
- 并行分支：T-003、T-004 无依赖，可立即执行
- 调度日志 + 工人状态表

### 2. 工人协议 (`.claude/dispatch/WORKER_PROTOCOL.md`)

- **11 步标准循环**：读主板 → 认领 → 执行 → 完成 → 解锁依赖 → 写报告 → 循环
- 每个步骤都是具体操作指令（Read BOARD.md, Edit BOARD.md, Read CLAUDE.md 等）
- 工人完成一个任务后自动接下一个，不等待用户指令
- 包含竞争防护：认领前检查 ⬜ → 🔵，不抢别人的任务

### 3. 调度员协议 (`.claude/dispatch/DISPATCHER.md`)

- **11 步巡检循环**：每分钟执行一次
- 检查工人超时、任务完成、阻塞处理、关键路径状态
- 通过 CronCreate 自动触发

### 4. CLAUDE.md 更新

- 调度系统放在最顶部（最高优先级）
- 任何新 Claude Code 会话启动时必须先读 BOARD.md 和 WORKER_PROTOCOL.md
- 明确写："不要停下来问用户接下来做什么"

### 5. 自动刷新机制

- CronCreate：每分钟触发调度员巡检
- 调度员静默运行，只在有进展时汇报

## 未解决问题

1. **调度系统尚未实战验证**：工人还没上线，7 个任务都处于 ⬜ 待认领状态。需要上级启动 3-4 个 Claude Code 会话来测试。
2. **竞争条件**：如果两个工人同时读 BOARD.md 并认领同一任务，目前靠"先标记先得"的惯例，没有文件锁。考虑到文件通过 mutagen 同步有几秒延迟，低概率但可能。
3. **调度员单点故障**：如果调度员会话（本会话）断开了，CronCreate 失效。工人仍能自主循环（读主板 + 认领任务），但不会有新任务被创建，也不会有超时监控。

## 给下一轮的经验教训

1. **指令要写到可执行的程度**：不是"检查新任务"而是"[1] Read BOARD.md, [2] 扫描 ⬜ 任务..."。工人不会猜测你的意图。
2. **工人和调度员有重叠职责**：工人在完成任务时也应该解锁依赖，不依赖调度员来做。双重覆盖比单一依赖更健壮。
3. **主板是唯一的协调点**：所有状态都在 BOARD.md 中，不依赖内存、不依赖数据库。即使调度员挂了，工人读一下主板就知道该干什么。
