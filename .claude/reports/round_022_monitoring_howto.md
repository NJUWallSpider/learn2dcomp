## /loop 是 Claude Code 内设功能

`/loop` 是 Claude Code **内置的 skill**（斜杠命令），不是外挂脚本。底层调用 `CronCreate` 工具注册 cron 表达式，由 Claude Code 运行时在后台按时唤醒当前会话。

### 用法

```
/loop 3m 检测V100训练状态，只读不干扰
```

解析规则：
- 以 `Nm`/`Nh`/`Nd` 开头 → 间隔
- 以 `every Nm` 结尾 → 间隔
- 都没有 → 默认 10 分钟

Cron 最小粒度是 **1 分钟**（不支持秒级）。每次触发时，Claude Code 自动把 prompt 文本注入当前会话并执行。

### 我的监控命令长什么样

每次触发的 prompt：

```
检测V100服务器状态，包含三部分：

1. 训练状态：SSH到V100执行 — nvidia-smi查询GPU状态、
   检查03_train_gnn进程、tail -3 log_step3.txt。只读不干扰。

2. 新报告检测：检查服务器 .../reports/ 下24h内新增的.md报告。
   有新报告则读取并摘要。

3. 同级Claude活动：检查本地 .../reports/ 下最近报告、
   check最近30分钟内修改的项目文件数量、本地claude进程数量。
```

一次 SSH 调用用 `&&` 串联所有检查，避免反复登录。

## 为什么其他工人（alpha/beta/gamma/delta）做不到

### 1. 工人协议设计目标不同

`WORKER_PROTOCOL.md` 设计的是**一次性任务执行模式**：

```
启动 → 读主板 → 认领任务 → 执行 → 写报告 → 认领下一个 → ...
```

工人完成任务后就该退出，不是为长期值守设计的。`/loop` 需要**一个会话持续存活**才能反复触发。

### 2. CLAUDE.md 没有教 /loop

项目手册（CLAUDE.md）详细写了调度系统、基础设施、安全规则，但没有提到 `/loop` skill 的存在和用法。工人不知道有这个工具。

### 3. 工人容易"死掉"

- 完成任务后主动退出
- 上下文压缩后丢失任务链
- 认领不到任务就"空闲等待"但实际已经断了
- 不像监控会话这样有 cron 保活

### 4. 权限差异

部分工人用 `--dangerously-skip-permissions` 启动，可能是为了跳过交互式确认。但 `/loop` 不需要特殊权限，它是标准功能。

## 实践经验

### 安全原则

- **所有 SSH 命令只读**：`nvidia-smi`、`ps aux`、`tail`、`find`、`wc -l`、`ls`
- **绝不 kill/rm/killall**
- **超时保护**：`ConnectTimeout=10`，2 分钟无响应就放弃
- **SSH alias 容错**：`10.0.0.13` 不通时换 `V100` alias

### 信息密度

- 一次 SSH 调用串联所有检查（用 `&&`），减少登录次数
- 输出格式统一：`===SECTION===` 分隔，方便肉眼扫描
- 变更量大的时候展开看，没变化就一句话带过

### Cron job 管理

- `/loop` 创建的 cron job 有 7 天自动过期
- 可以用 `CronDelete <job_id>` 手动取消
- Commit 自动化和监控是两个独立的 cron job

## 给项目的建议

1. **在 CLAUDE.md 加入 /loop 说明**：工人如果需要持续监控（如跟踪长时间 benchmark），可以用 `/loop` 设置定时检查
2. **调度员可以分配"监控岗"**：专门一个 worker 负责 `/loop` 值守，监控所有长时间任务和资源状态
3. **监控报告格式标准化**：每次检测的汇报格式保持一致（GPU/进程/报告/活动），便于快速扫描
